## 队伍成员平等管理

队伍资料与数据库移除负责人字段。所有当前成员均可增删成员、改名、归档和删除，创建者没有额外权限，也可以退出；成员被移除后失去管理权限。进行中和已归档队伍统一按当前成员集合唯一，顺序、大小写及队名不影响去重；修改或退出撞到已有组合时拒绝整个事务。

归档保留队伍并退出团队榜，删除永久移除队伍、成员关系及队伍操作记录，个人账号和成绩保留。`POST /api/teams/:id/archive` 用于归档，`DELETE /api/teams/:id` 用于删除。`0010_equal_team_members` 将旧库的重复组合合并至进行中队伍或最早的归档队伍，保留成员关系历史和操作记录；readiness 要求 11 项业务迁移。

Node.js 24.21.0 下类型检查、Lint、181 项单元测试、生产构建、`teams:verify`、`cf:shared:verify` 及 `personal:verify --http` 通过。专项验证覆盖旧库迁移、并发去重、全员管理权限、权限撤销、归档去重、创建者退出和删除清理；Chromium 验证非创建者改名、添加/移除成员及归档、归档队伍删除，桌面与 390px 手机布局正常。验证只修改随机隔离测试库，本次源码修改尚未迁移或更新运行中的正式服务。

## 2026-10-03 结构与操作优化

保留 `apps/web`、`apps/worker` 两个运行入口及 `core`、`db`、`connectors` 三个共享包，原公开服务导出、HTTP 路由和 CLI 命令兼容。

| 位置 | 职责 |
| --- | --- |
| `core/application/members` | 资料、账号候选与生效绑定 |
| `core/application/scores` | 成绩查询、个人/团队共用日期、计分表达式与查询元信息 |
| `core/application/collection/personal-sync` | 管理同步接口、单批执行及恢复 |

Lint 约束客户端、领域、数据库、连接器及 worker 的依赖边界。worker 的维护 SQL 由数据库 helpers 执行；业务页面经应用服务读取设置。单页归属重算限定本页提交，绑定变化限定旧、新账号；队伍列表批量读取成员。浏览器请求共用错误处理与取消信号，旧轮询响应不能覆盖新操作，未保存表单不被轮询刷新；替换账号说明历史贡献影响，重复建队明确展示复用结果及链接。

## 已交付的采集策略

- 首次扫描近 30 个北京时间日，保存固定下界，不设固定日期上界。每批最多 3 页、120 秒，页数或时间耗尽自动续跑。
- 只有整轮完成才发布持久增量检查点和初始化完成时间；正常空账号也完成初始化。随后从首页结合平台重叠窗口追赶新提交，停机超过 30 天不会截断成新的 30 天窗口。
- 每页题目、提交、归属、恢复游标与进度在同一事务提交；暂停、重启、平台重新鉴权后按保存进度恢复。
- 榜单日期只控制查询，不取消同步、不清空检查点。显式 `from/to` 是区间补采；`backfill` 无日期默认近 30 天，补采不推进持续增量检查点。
- `sync_runs.scope` 为 `initial/incremental/range`，首次保存 `initial_from`；`sync_cursors.initialized_at` 区分空账号与未初始化账号。升级保留旧事实与区间任务，旧区间检查点经一次安全的近 30 天初始化后转换到新策略。
- 首次窗口完成仍不证明全部历史完整，首次 AC、积分和名次继续按覆盖状态标为暂定。更早历史由管理员按需补采。

操作与迁移见[管理员采集管理](管理员采集管理.md)，浏览器会话保留更新流程见[个人后端与 Web 登录](个人后端与Web登录.md)。
