# 成员页面与团队榜

管理员与成员共用 `/login` 和 `/api/auth/login`。注册自动登录且只创建 member。姓名选填，可在 `/profile` 修改；显示名依次使用真实姓名、已验证 CF handle、本站用户名。

## 页面

| 地址 | 功能 |
| --- | --- |
| `/` | 个人榜、日期与平台筛选、分页 |
| `/members/:id` | 排名、平台账号、每日成绩、首次 AC 题目与原始提交 |
| `/profile` | 姓名、CF/QOJ 用户名和洛谷 UID，验证状态、同步、替换与解绑 |
| `/teams` | 我的队伍、已归档队伍、搜索本站成员并创建队伍 |
| `/teams/:id` | 团队成绩、成员贡献；所有当前成员均可改名、增删成员、归档、退出或删除 |
| `/team-leaderboard` | 团队排名、当前成员、积分、题数与数据完整性 |

普通页面只读取本站数据。账号候选由现有 worker 验证；采集暂停或平台未启用时保存候选并等待。验证失败保留原生效账号；解绑立即撤销旧账号个人历史贡献。

组队时输入关键词即可查找成员，停顿 350 毫秒后自动搜索；连续输入合并请求，中文输入法组词期间不发送搜索。修改关键词会取消旧请求、回到第一页并清除旧结果；清空输入不查询全部成员。支持实名、本站用户名、生效 CF / QOJ 账号及洛谷 UID，同一成员多个平台匹配时只出现一次。

## 团队口径

团队为当前成员在完整所选区间内的个人积分和题数之和，包括入队前的区间成绩。v2 将 CF 组队 AC 纳入个人归属，积分按完整实际队伍人数平均分摊，未绑定队员也计入分母；例如原值 5 分、3 人组队，每人得 5/3 分，三人的团队合计 5 分。题数仍是每人各计一道，再按当前成员相加，三人共同 AC 一题可贡献 3 道成员题数。每人同一题只取首次有效 AC 的分摊，后续个人或组队 AC 不重复计分。小数不先取整，页面显示最多三位小数。不同成员完成同题时分别贡献，成员更换或解绑后立即反映新结果。停用成员贡献为零。归档队伍保留最后的剩余成员，详情仍动态计算，退出团队榜且名次为 null。

默认沿用管理员的平台及计分区间；支持近 7/30 天、自定义北京时间首尾日期和单平台，最多 366 天。个人先从全部有效历史求首次 AC，再筛区间；团队复用该结果。积分、题数、最近首次 AC 依次降序，完全相同采用 1、1、3 的并列排名，ID 只保证稳定显示顺序。历史未完整或存在权限缺口时成绩暂定。

队伍没有负责人，创建者是普通成员。所有当前成员权限平等，均可改名、增删成员、归档和删除；成员被移除后立即失去管理权限。创建者须包含在初始 2—3 人集合中，创建后也可退出或被移除。

所有队伍（含已归档队伍）的排序成员 ID 集合有数据库唯一索引，队名、成员顺序和创建者不影响去重；创建/改人/退出事务串行处理。重复创建返回已有 ID，保留原名称与归档状态；修改成员或退出撞到已有组合时返回冲突且不改动队伍。成员改动保留关系历史和操作记录，退出后不足两人时自动归档。归档保留队伍，不能编辑；当前剩余成员仍可删除。删除永久移除队伍、成员关系及队伍操作记录，保留个人账号和成绩，随后可重新创建该组合。

## 接口

所有读取要求登录；写入额外校验 Origin、CSRF 和对象权限，响应为 no-store。

| 方法和地址 | 输入 / 返回 |
| --- | --- |
| `GET /api/members` | `q/page/limit`；按用户名、真实姓名、生效 CF / QOJ 账号或洛谷 UID 搜索；默认 20 条，最多 100 |
| `GET /api/teams` | `mine=0\|1`、`status=active\|archived`、`page/limit`；默认有效队伍 |
| `POST /api/teams` | `{name,memberIds}`；2—3 个成员 ID，包含当前用户；新建 201，重复返回已有队伍 200；`{id,created}` |
| `PUT /api/teams/:id` | `{name,memberIds,version}`；任意当前成员可改名及增删成员 |
| `POST /api/teams/:id/archive` | `{version}`；任意当前成员归档 |
| `DELETE /api/teams/:id` | `{version}`；任意当前成员永久删除进行中或已归档队伍 |
| `DELETE /api/teams/:id/members/me` | `{version}`；任意当前成员退出；返回 `{id,archived}`；剩余组合重复时返回 409 和已有 `teamId` |
| `GET /api/team-leaderboard` | 与个人榜相同的日期、平台、分页参数 |
| `GET /api/teams/:id` | 相同计分参数；队伍、当前成员贡献、总分、排名和完整性 |

队名为去除首尾空格后的 1—64 字。成员不存在或停用返回 400，无权限 403，不存在 404，版本冲突/已归档/成员组合冲突 409。组合冲突额外返回 `teamId`，供链接到已有队伍。成员明细补充 `rank` 和仅含生效账号的 `platformAccounts`，候选和个人绑定错误只在本人资料接口展示。

## 组队分摊验证

`pnpm cf:shared:verify` 在独立临时数据库中验证从 v1 迁移、部分成员绑定、2/3 人分摊、各统计页面一致、重复归属重算、成员解绑重绑、首次 AC 去重、重判和 ghost/不一致作者证据。成功后删除验证数据库，失败时保留隔离库名称用于排查，不修改业务数据。
